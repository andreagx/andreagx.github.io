Dal **16 novembre 2026**, Virtualization Mode (vMode) è in disponibilità generale con **Windows Admin Center 2611**. Microsoft lo presenta come un piano di gestione centralizzato per host Hyper-V standalone e cluster Windows Server, insieme alle risorse di rete e storage associate. Una singola istanza può gestire fino a **1.000 host e 25.000 VM** secondo i limiti dichiarati. La console può gestire host Windows Server 2022 e 2025 idonei, quindi il suo utilizzo è indipendente dall’arrivo di Windows Server 2028. [Annuncio della versione 2611](https://techcommunity.microsoft.com/blog/windows-admin-center-blog/virtualization-mode-in-windows-admin-center-is-now-generally-available/4573651) · [Requisiti per gli host gestiti](https://learn.microsoft.com/en-us/windows-server/manage/windows-admin-center/add-virtualization-mode-resources)

## Due modalità, due architetture

L’installer di Windows Admin Center 2611 offre **Administration Mode (aMode)** e **Virtualization Mode (vMode)**. aMode è la modalità di amministrazione generale dei server, con un gateway senza database. vMode usa invece un gateway con stato persistente, un database **PostgreSQL gestito dal prodotto** e agenti installati sugli host Hyper-V. Il gateway autentica gli utenti, instrada le richieste e conserva l’inventario e la configurazione. Gli agenti eseguono le operazioni sugli host e le comunicazioni con il gateway sono protette da TLS. Per cambiare modalità dopo l’installazione occorre reinstallare Windows Admin Center. [Installazione di Windows Admin Center](https://learn.microsoft.com/en-us/windows-server/manage/windows-admin-center/deploy/install) · [Architettura di Virtualization Mode](https://learn.microsoft.com/en-us/windows-server/manage/windows-admin-center/virtualization-mode-overview)

Il gateway è il piano di gestione. L’esecuzione delle VM e il failover dei ruoli cluster restano responsabilità degli host e di Failover Clustering. I limiti di scala della console descrivono quindi quanti oggetti può amministrare un’istanza, indipendentemente dai limiti di dimensionamento di ciascun cluster Hyper-V. Analogamente, la disponibilità delle VM e il ripristino del gateway sono aspetti distinti. [Architettura di Virtualization Mode](https://learn.microsoft.com/en-us/windows-server/manage/windows-admin-center/virtualization-mode-overview)

## Requisiti: gateway, host e guest

| Livello | Requisiti documentati |
| --- | --- |
| **Gateway vMode** | Macchina dedicata Windows Server, fisica o virtuale. Microsoft documenta Windows Server 2025 Standard o Datacenter, join al dominio e risoluzione DNS tramite FQDN. |
| **Host Hyper-V gestiti** | Windows Server 2025 oppure Windows Server 2022 con l’aggiornamento cumulativo di marzo 2026 o successivo. La guida all’onboarding indica le edizioni Standard e Datacenter supportate, almeno 4 CPU virtuali o core equivalenti, 8 GB di RAM e 10 GB liberi. |
| **Identità e raggiungibilità** | Gli host devono appartenere allo stesso dominio Active Directory del gateway e risolversi tramite FQDN. L’onboarding richiede un account con i diritti amministrativi locali sui nodi. Ogni host può essere gestito da una sola istanza vMode. |
| **Guest** | I requisiti del sistema operativo degli host riguardano la piattaforma gestita. La compatibilità dei guest segue il supporto Hyper-V. |

La guida aggiornata all’onboarding richiede **SMB, accesso alla share amministrativa `C$` e WinRM** tra gateway e host. Indica di mantenere disponibili SMB-In e `C$` per tutta la gestione della risorsa, perché sono usati per distribuire, aggiornare o rimuovere l’agente e per operazioni di gestione. Questa indicazione è più recente di quella pubblicata durante la preview, che descriveva SMB come requisito temporaneo. [Installazione del gateway](https://learn.microsoft.com/en-us/windows-server/manage/windows-admin-center/deploy/install) · [Prerequisiti degli host e del firewall](https://learn.microsoft.com/en-us/windows-server/manage/windows-admin-center/add-virtualization-mode-resources#prerequisites)

## Inventario, cluster e Network ATC

I **resource group** di vMode organizzano host, cluster e risorse associate. Sono contenitori interni al gateway e ogni host appartiene a un solo gruppo. La console presenta viste Compute, Storage e Network e consente di cercare risorse nell’inventario, rispettando le autorizzazioni dell’utente. Il wizard può aggiungere un host standalone, acquisire un cluster esistente dal suo FQDN o creare un cluster da almeno due host. Include anche impostazioni Hyper-V come il percorso predefinito delle VM e il numero di live migration concorrenti. [Onboarding delle risorse Compute](https://learn.microsoft.com/en-us/windows-server/manage/windows-admin-center/add-virtualization-mode-resources)

Per i cluster, **Network ATC** applica intenti dichiarativi alle schede fisiche. Il template memorizza la configurazione riutilizzabile e l’onboarding la associa alle NIC effettive. Il flusso richiede esattamente un intento con **Management** e almeno uno con **Compute**. Un solo intento può comprendere entrambi. Un intento **Storage** è raccomandato per Storage Spaces Direct e storage Ethernet come SMB, ed è facoltativo per SAN esterne. Gli host che rimangono standalone possono essere aggiunti senza configurare intenti Network ATC. [Novità di rete nella GA](https://techcommunity.microsoft.com/blog/windows-admin-center-blog/networking-improvements-in-windows-admin-center-virtualization-mode-ga/4573448)

Nella creazione di un cluster nuovo, la procedura verifica gli intenti prima di avviare il clustering. La rimozione di un intento preesistente lascia in sede gli oggetti già creati, come un virtual switch. La nuova configurazione può quindi incontrare oggetti residui. La 2611 introduce una convalida anticipata e, dove disponibili, mostra gli eventi Network ATC dei nodi in caso di errore. [Pre-validazione e diagnostica Network ATC](https://techcommunity.microsoft.com/blog/windows-admin-center-blog/networking-improvements-in-windows-admin-center-virtualization-mode-ga/4573448)

## Storage: cosa fa la console

Con **Windows Scale-Out File Server**, la procedura verifica il percorso della share, installa l’agente sul file server e può configurare autorizzazioni SMB e delega per la live migration quando dispone dei permessi necessari. Con un **file server SMB non Windows** registra invece il percorso UNC dopo averne verificato l’accessibilità. Le funzioni di configurazione automatica dei permessi e della delega sono specifiche dello scenario Windows. Per una **SAN Fibre Channel o iSCSI**, il wizard individua le LUN condivise durante l’onboarding degli host e indica quali sono utilizzabili, configurabili automaticamente o da preparare manualmente. Lo storage già connesso agli host può essere riutilizzato. [Storage e onboarding nella 2611](https://techcommunity.microsoft.com/blog/windows-admin-center-blog/virtualization-mode-in-windows-admin-center-is-now-generally-available/4573651) · [Configurazione delle risorse Compute](https://learn.microsoft.com/en-us/windows-server/manage/windows-admin-center/add-virtualization-mode-resources)

## Delega e certificati

L’accesso al gateway usa l’autenticazione Windows con account Active Directory. Il controllo **RBAC di vMode** governa le operazioni nella console e si può assegnare alla radice, a un resource group, a un cluster o a un host. Le assegnazioni si propagano agli oggetti sottostanti. I ruoli integrati sono **Global Administrator**, per il controllo del gateway, **Fabric Manager**, per la gestione dell’infrastruttura nell’ambito assegnato, e **Reader**, per la consultazione. Per le operazioni sugli host continuano ad applicarsi anche le autorizzazioni Windows. Azure RBAC governa separatamente le operazioni sui servizi Azure. [Autenticazione e ruoli nella 2611](https://techcommunity.microsoft.com/blog/windows-admin-center-blog/virtualization-mode-in-windows-admin-center-is-now-generally-available/4573651)

Il certificato HTTPS presentato al browser e il ciclo di vita dei certificati usati tra gateway e nodi rispondono a esigenze distinte. La 2611 integra **Active Directory Certificate Services (AD CS)** per l’emissione tramite template e il rinnovo automatizzato dei certificati vMode. L’onboarding ad **Azure Arc** avviene per macchina e può essere avviato in blocco. Il gateway installa l’Azure Connected Machine Agent e applica le impostazioni Azure selezionate. La release documenta la connessione a endpoint pubblici, direttamente o tramite proxy. [Installazione e certificato HTTPS](https://learn.microsoft.com/en-us/windows-server/manage/windows-admin-center/deploy/install) · [Certificati e Azure Arc nella 2611](https://techcommunity.microsoft.com/blog/windows-admin-center-blog/virtualization-mode-in-windows-admin-center-is-now-generally-available/4573651)

## Ripristino del gateway e replica delle VM

Il backup integrato crea una copia **cifrata e protetta da password del database di gestione**, salvabile su cartella locale o share UNC. Include inventario, metadati dei cluster, configurazione del gateway, ruoli e template. Il ripristino riporta il database allo stato della copia. Gli agenti riconnessi riportano quindi lo stato corrente di host e VM. Il recupero dei dischi virtuali e dei dati applicativi richiede strumenti di protezione dei workload. Durante l’aggiornamento, l’installer conserva il database e la configurazione. Gli agenti si riconnettono e vengono aggiornati dal gateway secondo necessità. [Backup, ripristino e aggiornamento nella 2611](https://techcommunity.microsoft.com/blog/windows-admin-center-blog/virtualization-mode-in-windows-admin-center-is-now-generally-available/4573651)

Per **Hyper-V Replica**, la console consente di configurare Replica Broker, trasporto HTTP o HTTPS, dischi, frequenza, punti di recupero e copia iniziale. Espone lo stato della replica e operazioni come test failover, failover pianificato o non pianificato, reverse replication ed extended replication. Il **Replication Monitor**, che aggrega lo stato su più host e cluster, è stato annunciato separatamente in **private preview**. [Hyper-V Replica e Replication Monitor nella 2611](https://techcommunity.microsoft.com/blog/windows-admin-center-blog/virtualization-mode-in-windows-admin-center-is-now-generally-available/4573651)

## Funzioni ancora in anteprima

La disponibilità generale riguarda vMode. Microsoft colloca ancora in **private preview** la nuova appliance di conversione **VMware ESXi → Hyper-V**, con pre-verifiche, sincronizzazione prima del cutover e operazioni in batch, e l’integrazione **Trusted Launch** per visualizzare in vMode lo stato di integrità dell’avvio delle VM supportate. La seconda dipende anche dalle build Windows Server Insider e dal perimetro di supporto di Trusted Launch. [Annuncio VM Conversion](https://techcommunity.microsoft.com/blog/windows-admin-center-blog/virtualization-mode-in-windows-admin-center-is-now-generally-available/4573651) · [Anteprima privata Trusted Launch in vMode](https://techcommunity.microsoft.com/blog/windows-admin-center-blog/tvm-in-windows-admin-center-vmode-is-in-private-preview/4574161)
